📖 Summary — Master Class (Longer-Form Companion)

The consolidated study companion synthesizing the core concepts across all 12 videos. Read after watching, or as a rapid interview refresher.

One-Sentence Thesis: SAM reconciles what you own (entitlements) against what exists and is used (normalized installs + usage) per software model and license metric, and turns the difference into a compliance position.

The Master Chain (I-D-S-E-R)

CI (CMDB/IRE)
  └─ cmdb_sam_sw_install            # one install on one device
       └─ cmdb_sam_sw_discovery_model  # raw fingerprint → normalized
            └─ cmdb_software_product_model  # purchased product profile
                 └─ alm_license             # rights + metric + dates
                      └─ reconciliation     # rights vs demand
                           ├─ samp_product_result
                           ├─ Software Model Results
                           └─ samp_license_metric_result
Software model = what it IS. Entitlement = what you MAY USE. Installation = what EXISTS. Usage = what is USED. Reconciliation = the DIFFERENCE.

Compliance Positions

PositionMeaningAction
CompliantOwned ≥ demandMonitor
Over-licensedOwned > demandReclaim / renegotiate
Under-licensedOwned < demandTrue-up or reclaim
UnlicensedNo entitlementRemove / purchase
Not countedExcluded by ruleReview annually
UnknownInsufficient dataFix data — NOT compliant
"Unknown" is NOT "Compliant" — reporting unknown as compliant hides audit exposure.

Top 8 Traps

  1. Metric mismatch — silently meaningless result
  2. Duplicate installs — inflated demand
  3. Unnormalized titles — unlicensed/unknown
  4. Maintenance treated as license — false compliance
  5. Leftover installs on out-of-scope devices — phantom demand
  6. First reconciliation as invoice — wrong true-up
  7. Dead SaaS connector — "no waste" illusion
  8. Confusing vendor/publisher/PPN/model/catalog — wrong links
